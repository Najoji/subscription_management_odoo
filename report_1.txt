2. TECHNICAL IMPLEMENTATION DETAILS
================================================================================

A. CENTRAL PRICING SERVICE (decimal.js paise precision)
- Unit Price = Product Sales Price + Selected Variant Extra Price
- Line Subtotal = Unit Price * Quantity
- Eligible Discount = Fixed or Percentage applied to subtotal (capped at subtotal)
- Taxable Base = Line Subtotal - Discount
- Tax Amount = Taxable Base * (Tax Rate / 100)
- Final Line Total = Taxable Base + Tax Amount
Verification Example (matches specification exactly):
  Base Product: Rs. 1,000.00
  Variant Extra: Rs. 560.00
  Quantity: 2
  Unit Price: Rs. 1,560.00
  Line Subtotal: Rs. 3,120.00
  10% Discount: Rs. 312.00
  Taxable Amount: Rs. 2,808.00
  18% Tax: Rs. 505.44
  Final Total: Rs. 3,313.44

B. BILLING ENGINE (POST /api/billing/run)
- Accepts optional { "asOfDate": "YYYY-MM-DD" }, defaults to current date.
- Scans for subscriptions where status = 'Active' and next_billing_date <= asOfDate.
- Ignores 'Draft', 'Quotation', 'Paused', and 'Closed' subscriptions.
- Missed billing periods: If a subscription is multiple billing cycles overdue,
  it catches up sequentially, creating separate invoices for each period up to asOfDate.
- Duplicate prevention: Uses database constraint UNIQUE(subscription_id, period_start).
  Running billing twice never generates a duplicate invoice for an already processed period.
- Creates immutable snapshot invoice line items in invoice_items.
- Advances subscriptions.next_billing_date to period_end.
- Sets initial invoice status to 'Draft' (never marked Paid automatically).

C. DISCOUNT MANAGEMENT (/api/discounts)
- Supports fixed and percentage discounts.
- Enforces validity rules:
  1. Active status check (is_active = true)
  2. Date validity window (start_at <= today <= end_at)
  3. Minimum spend threshold (subtotal >= minimum_purchase)
  4. Minimum quantity check (quantity >= minimum_quantity)
  5. Usage limits (usage_count < usage_limit)
  6. Caps discount amount to never exceed eligible subtotal.

D. INVOICE MANAGEMENT (/api/invoices)
- GET /api/invoices: Pagination, search by invoice_number, filter by customerId,
  subscriptionId, status, date range, and isOverdue (Confirmed, past due date, unpaid).
- GET /api/invoices/:id: Returns full snapshot details, customer info, subscription,
  billing period, line items, taxes, recorded payments, and remaining balance.
- POST /api/invoices/:id/confirm: Moves invoice from 'Draft' to 'Confirmed'.
- POST /api/invoices/:id/cancel: Cancels eligible invoices. Strictly forbids
  cancelling invoices that have recorded payments.

E. PAYMENT MANAGEMENT (/api/payments & /api/invoices/:id/payments)
- Supported methods: 'Cash', 'UPI', 'Card', 'Bank Transfer', 'Other'.
- Validates payment amount > 0 and amount <= remaining invoice balance.
- Prevents payments against 'Cancelled' invoices.
- Increments amount_paid and tracks received_by user ID.
- Status progression rule:
  - If new_balance > 0: status remains 'Confirmed' (partial payment).
  - If new_balance == 0: status automatically updates to 'Paid'.

F. DASHBOARD ANALYTICS (GET /api/dashboard/summary)
- Returns real-time KPI metrics aggregated directly via database queries:
  1. activeSubscriptions: count of 'Active' subscriptions.
  2. totalSubscriptions: total count of all subscriptions.
  3. revenueCollected: sum of actual recorded payments (not billed invoices).
  4. outstandingAmount: sum of unpaid balances on confirmed invoices.
  5. overdueInvoices: count of confirmed invoices where due_date < today and unpaid.
  6. subscriptionStatusCounts: counts grouped by status (Active, Draft, Closed, etc.).
  7. revenueByPeriod: monthly revenue trend array ([ { period: '2026-10', revenue: ... } ]).

G. SECURITY & RBAC
- Admin: Full access across billing runs, discounts, invoices, payments, dashboard.
- Staff: Operational access to billing runs, invoice confirmation, payments, dashboard.
- Customer: View only their own invoices and payments (isolated by customer_id).
